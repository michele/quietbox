# `quietbox stats` Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A read-only `quietbox stats [--since 30d] [--json]` that reports estimated time saved, where mail went (per folder and rule) and the error rate, computed from the existing SQLite tables.

**Architecture:** A pure `internal/stats` package turns plain row structs into a `Report` and renders it. `internal/store` gets one new read method; the audit log is read with the existing `AuditSince`. A thin cobra command in `cmd/quietbox` wires config, store and `stats`. No schema change, no lock, no IMAP.

**Tech Stack:** Go, `modernc.org/sqlite` via `internal/store`, cobra, TOML config. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-26-stats-design.md`

## Global Constraints

- No new dependencies; no schema migration; nothing is written to the database or the mailbox.
- `internal/stats` is pure: no `database/sql`, no IMAP, no `os`; it writes only to the `io.Writer` it is given.
- Output never contains addresses, subjects or bodies: folders, rules and counts only.
- Time saved is always labelled an estimate. Default `[stats] seconds_per_message = 5`, positive integer.
- Error rate = corrections / filed, shown as a floor (the output says it only counts mistakes you fixed).
- Retention purges (rule `retention`) are not "filed" and never corrections.
- `make test` (with `-race`) and `make lint` are clean before each commit. Conventional commit messages, each ending with the line `Claude-Session: https://claude.ai/code/session_01CUS7msYe81mSFUyxHhH6Nj`.
- Done also means: run end to end against the Docker test server with the command output shown (Task 5); say so explicitly if anything could not be verified.

## Review Focus

- No moves in the window: `Filed` 0, no division by zero, error rate printed as `n/a`.
- Moves with status `planned` or `failed` are not counted as filed.
- A training event that is older than the move for the same message key is not a correction.
- A message you drag back and forth counts as one correction, not two.
- The database does not exist yet (`init` never run): the command fails with the existing "run `quietbox init` first" message and creates no file.

### Task 3: `internal/stats` (pure)

**Files:**

**Interfaces:**
- Produces (exact names; later tasks use them):

```go
type Move struct {
	Key, From, To, Reason string // Reason is stored as "<rule>: <text>"
	At                    time.Time
	Done, Undone          bool // Done: audit status "done"
}
type Event struct {
	At             time.Time
	Sender, Folder string // Folder is the new route; Sender is only used to count distinct retrained senders
	Key            string
	ByMove         bool // false for `senders set` (manual)
}
type Input struct {
	Moves             []Move
	Events            []Event
	Now               time.Time
	Window            time.Duration
	SecondsPerMessage int
	Inbox             string   // name of the INBOX folder
	FolderOrder       []string // config order; unknown folders sort after, alphabetically
	RetentionRule     string   // rule name of retention purges (engine.RuleRetention)
}
type RuleCount struct{ Rule string; Count int }
type FolderStat struct {
	Folder string; Count int; Share float64; Purged int; Rules []RuleCount // Rules: count desc, then name
}
type Report struct {
	Since, Until          time.Time
	Filed, SavedSeconds   int
	SecondsPerMessage     int // echoed from Input, for the "(N s each)" label
	Folders               []FolderStat
	Corrected, BackToInbox, Refiled, Undone, Retrained int
	ErrorRate             float64 // 0 when Filed == 0
}
func Compute(in Input) Report
func FormatSaved(seconds int) string            // "42 s", "34 min", "2 h 5 min"
func WriteText(w io.Writer, r Report, account string) error
```

All `Report` fields carry snake_case `json` tags (`filed`, `saved_seconds`, `seconds_per_message`, `folders`, `corrected`, `back_to_inbox`, `refiled`, `undone`, `retrained`, `error_rate`, `since`, `until`; `FolderStat`: `folder`, `count`, `share`, `purged`, `rules`; `RuleCount`: `rule`, `count`).

- [ ] **Step 1: Write failing table tests for `Compute`** (`TestComputeFiledAndFolders`, `TestComputeRules`, `TestComputeCorrections`, `TestComputeUndoneAndRetrained`, `TestComputePurges`, `TestComputeEmpty`), each with the cases below. Use a fixed `Now` and a 30-day `Window`; the window start is `Now - Window`, moves before it are ignored.
  - Filed/folders: 3 done moves to `+News`, 1 to `+Bulk`, 1 `failed`, 1 `planned` -> `Filed == 4`, `SavedSeconds == 4*SecondsPerMessage`, folders ordered by `FolderOrder`, `Share` 0.75 and 0.25.
  - Rules: reasons `"sender: route to +News"`, `"newsletter: ..."`, a reason with no `": "` -> rule `other`; rules counted per folder.
  - Corrections: a `ByMove` event for a filed key at/after the move, `Folder == Inbox` -> `BackToInbox` 1; `Folder == "+Bulk"` -> `Refiled` 1; an event dated before its move -> not a correction; two events for one key -> `Corrected` 1 (the later one decides the kind); a manual event (`ByMove false`) -> not a correction but its sender counts in `Retrained`; an event for a key whose move is `Undone` -> not a correction.
  - Undone/retrained: `Undone` counts done moves flagged `Undone`; `Retrained` is the number of distinct `Sender`s across all events in `Events`.
  - Purges: a done move whose rule is `RetentionRule` and `From` is the blackhole folder -> not in `Filed`; it adds to `Purged` on the folder it left (a `FolderStat` with `Count 0` is created if that folder had no filed mail).
  - Empty: no moves -> `Filed 0`, `ErrorRate 0`, empty `Folders`, no panic.
  - `ErrorRate == Corrected / Filed` (e.g. 2 of 8 -> 0.25).
- [ ] **Step 2: Write failing render tests**: `TestFormatSaved` (`0`->`0 s`, `42`->`42 s`, `60`->`1 min`, `2040`->`34 min`, `7500`->`2 h 5 min`); `TestWriteText` builds a `Report` by hand and asserts the output contains `Filed away`, `est. time saved`, a folder line with count and percentage, a rule split, `Corrected by you`, `dragged back to INBOX`, `Undone with undo`, and, for `Filed == 0`, the text `error rate n/a`; also asserts the line `counts only mistakes you fixed` appears whenever `Filed > 0`.
- [ ] **Step 3: Run** `go test ./internal/stats -race`; expect FAIL (package does not compile).
- [ ] **Step 4: Implement `Compute` in `stats.go`.** Rule = text before the first `": "` in `Reason`, else `other`. Index done, non-retention moves in the window by `Key`. A correction needs `ByMove`, a matching filed move that is not `Undone`, and `Event.At >= Move.At`; per key keep only the latest qualifying event. Move events whose key matches nothing are ignored.
- [ ] **Step 5: Implement `FormatSaved` and `WriteText` in `render.go`** following the layout below (a `text/tabwriter` is fine; exact spacing is free, the labels above are fixed):

```
Last 30 days (account: fastmail)
Filed away        412 messages    est. time saved ~34 min (5 s each)

Where it went
  +QuietNews      201  49%   sender 140 · newsletter 61
  +QuietBlackHole  12   3%   sender 12 · purged to Trash 4

Mistakes
  Corrected by you   9  2.2%   (dragged back to INBOX 6, re-filed elsewhere 3)
  Undone with undo   0
  Senders retrained  7
  Error rate counts only mistakes you fixed; wrongly hidden mail you never noticed is not in it.
```

  The window label is derived from `Until - Since` in whole days. The `(N s each)` part uses `Report.SecondsPerMessage`.
- [ ] **Step 6: Run** `go test ./internal/stats -race` and `make lint`; expect PASS and clean.
- [ ] **Step 7: Commit** `feat(stats): compute filed, breakdown and error rate from the audit log`.
