# M3: Run for real: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `quietbox once`, `quietbox run`, `--dry-run` and `quietbox undo --since` move new INBOX mail safely, with every move audited first and reversible.

**Architecture:** One `engine.Process` pass (cursor-based, new mail only) is used by `once` and by the `run` loop (IDLE + reconnect). Moves go through new `mail.Backend` methods; audit rows are written `planned` before the MOVE and completed with the COPYUID destination afterwards. `engine.Undo` reverses `done` moves.

**Tech Stack:** Go, go-imap v2 beta.9 (MOVE, IDLE, STATUS), modernc SQLite, cobra. No new dependencies.

**Spec:** `docs/superpowers/specs/2026-11-20-m3-run-design.md` (milestone text in `docs/PLAN.md`). Read `CLAUDE.md` first.

## Global Constraints

- Never expunge or permanently delete. Require server capabilities `MOVE` and `UIDPLUS`; otherwise refuse to run.
- **go-imap's `Client.Move` silently falls back to COPY + STORE `\Deleted` + EXPUNGE when MOVE is missing.** `imapbackend.Backend.Move` must check the capability itself and never reach that fallback.
- Audit row (`planned`) is committed before every mutation; `--dry-run` writes no audit rows, moves nothing, advances no cursor.
- Never log message bodies, subjects or credentials. Message key stays `mail.Key` (EMAILID deferred).
- `internal/classify` and `internal/learn` stay pure. `internal/mail` imports no IMAP library. Mailbox mutations only through `engine`; commands only parse flags.
- No new dependencies. Tests never touch a real mailbox; integration tests use the docker Dovecot server (`-tags integration`).
- Each task: tests first, `go test ./... -race` and `make lint` clean, one conventional commit ending with the line `Claude-Session: https://claude.ai/code/session_01CUS7msYe81mSFUyxHhH6Nj`.

## Review Focus

1. Server lacks MOVE/UIDPLUS: refuse before touching anything (Task 3, 5).
2. UIDVALIDITY of INBOX/Sent changed: nothing moves, cursor reset, user told to re-run `init` (Task 6).
3. Crash between audit `planned` and the MOVE: leftover `planned` rows get reconciled, not replayed blindly (Task 6).
4. Message dragged back to INBOX, or restored by `undo`: never moved again (Task 5, 7).
5. Undo when the message was moved elsewhere meanwhile, UIDVALIDITY changed, or the key is a hash (`h:`): skip and report, never abort the whole undo (Task 7).
6. `run` loses its connection: reconnect with backoff, no duplicate moves (Task 9).

  type MoveOutcome struct { From, To, Sender, Rule, Reason, Status string } // Status: done|failed|would_move

### Task 6: `Process`: Sent, UIDVALIDITY, reconcile, lock

**Files:** Modify `internal/engine/process.go`; Create `internal/engine/lock.go`; Test `process_test.go`, `lock_test.go`.

**Interfaces:**
- `func AcquireLock(path string) (release func(), err error)`: non-blocking `syscall.Flock` on `<state path>.lock`; a held lock returns an error saying another quietbox instance is running. Unix only (state in the build notes).
- Process (non-dry-run) takes the lock; dry-run does not.
- Order of Process: lock → `RequireMove` → reconcile → UIDVALIDITY check for INBOX and Sent → Sent step → INBOX step.
- Reconcile: each `planned` move row older than this pass: `Locate` in `to_folder` by message id from the key (`m:` keys only). Found → `SetAuditResult(done, dest)`; not found → `failed`. `h:` keys → `failed` with reason noted.
- UIDVALIDITY mismatch on a folder: skip that folder, `SetCursor` to the new (validity, UIDNext), add a `ProcessReport.Warnings` entry telling the user to re-run `quietbox init`. Nothing moves from INBOX when INBOX changed.
- Sent step: `FetchFrom` new, update `sent_to` and `sent_message_ids` (reuse the helpers in `learn.go`: `addSentRecipients`, `sentWhen`; add store `(*Tx).AddSent(rows []SentRow, ids []SentMsg)` that adds without replacing), advance cursor.

### Task 9: `run` daemon loop

**Files:** Create `internal/engine/run.go`, `cmd/quietbox/run.go`; Test `internal/engine/run_test.go`.

**Interfaces:**
```go
type RunOptions struct {
    Connect  func(ctx context.Context) (mail.Backend, error) // dial; called again after errors
    Backoff  func(attempt int) time.Duration                  // default: 5s doubling to 5m, reset after a clean pass
    Progress func(string)
}
func Run(ctx context.Context, cfg *config.Config, st *store.Store, o RunOptions) error
```
Loop: Connect → `Process` → `WaitForChange(INBOX)` → repeat. Any error from Connect, Process or WaitForChange closes the backend, waits `Backoff(attempt)` (respecting ctx) and reconnects. A refusal to run (missing MOVE/UIDPLUS, no cursor, lock held) is **fatal**, not retried. On ctx cancel it returns nil after the current pass. The command wires `signal.NotifyContext(SIGINT, SIGTERM)`.
