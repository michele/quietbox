# M4: Training via folder moves: Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** `once`/`run` learn from messages the user moves (into a typed folder: route the sender there; back to INBOX: keep the sender in INBOX), plus `quietbox explain` and `quietbox senders set/unset`.

**Architecture:** Arrivals only. Typed folders get UID cursors; each pass reads only new UIDs in typed folders and INBOX, drops arrivals the audit log explains (our own moves and undos), and turns the rest into trained sender routes *before* INBOX classification. A new `messages` table remembers which typed folder a message was last seen in, so a return to INBOX is recognisable. `classify` stays pure and nearly unchanged.

**Tech Stack:** Go, go-imap v2, modernc SQLite, cobra. No new dependency.

**Spec:** `docs/superpowers/specs/2026-11-21-m4-training-design.md` (read it first).

## Global Constraints

- Never expunge or delete mail; training never mutates the mailbox (spec: Safety).
- `internal/classify` and `internal/learn` stay pure: no I/O. `internal/mail` imports no IMAP library.
- Message key is `mail.Key(h)` (EMAILID, then Message-ID, then hash). Never log or store subjects/bodies.
- Schema changes are a **new** migration (v5) appended to `internal/store/migrations.go`; never edit an applied one.
- `--dry-run` writes nothing and takes no lock. `senders set`/`unset` take the instance lock and **wait** for it (print `waiting for another quietbox...` after 1 s, honour Ctrl-C).
- Tests never touch a real mailbox; integration tests use the Dovecot server (`make itest`).
- Done = tests with `-race` (`make test`), `make lint` clean, demo against the docker server with output shown, `docs/PLAN.md` M4 section and README updated. Conventional commits, one logical change each, each ending with `Claude-Session: https://claude.ai/code/session_01CUS7msYe81mSFUyxHhH6Nj`.

## Review Focus

Inputs the spec implies that are most likely to bite; each has a test in the named task.

1. A **second copy of an already-filed message** (same Message-ID, delivered later) lands in INBOX: it is new mail, it must not pin the sender to INBOX. (Task 4)
2. A message dragged back to INBOX is almost always `\Seen`: it must still train despite `skip_seen`. (Task 5)
3. An **M3 database** (no typed-folder cursors, empty `messages`): first M4 pass must not crash, must not train retroactively, and must say so. (Task 5)
4. A typed folder whose **UIDVALIDITY changed**: no training from it, cursor reset, warning. (Task 5)
5. A message **from your own address** (e.g. a Sent copy dragged into a folder) or with an unparseable From never trains. (Task 4)

### Task 4: arrival detection (pure logic)

**Files:** Create `internal/engine/train.go`, `internal/engine/train_test.go`.

**Interfaces (Produces):**
```go
type arrival struct {
    H        mail.Header // H.UID, H.InternalDate, H.From, H.MessageID set
    Key      string      // mail.Key(H)
    Folder   string      // folder it appeared in
    Validity uint32      // UIDVALIDITY of Folder when it was read
}
type trainEvent struct{ Sender, Folder, MessageKey string } // Folder == inbox means "keep in INBOX"

type ownMoves struct{ /* unexported */ }
func newOwnMoves(rows []store.AuditRow) *ownMoves
// explains: a done move/undo_move row with ToFolder == a.Folder and (DestUIDValidity, DestUID) == (a.Validity, a.H.UID);
// for rows with DestUID == 0, key and ToFolder match instead.
func (o *ownMoves) explains(a arrival) bool
// movedAt: the At of the latest done, not-undone move row for key.
func (o *ownMoves) movedAt(key string) (time.Time, bool)

func fileEvent(a arrival, me map[string]bool) (trainEvent, bool)     // false: own address or empty From
type returnVerdict int // notReturn | returnExplained | returnTrained
func inboxArrival(a arrival, inbox string, known map[string]store.MessageRow, own *ownMoves, me map[string]bool) (returnVerdict, trainEvent)
```
`inboxArrival` rules: `notReturn` unless the key is in `known` with `!a.H.InternalDate.After(row.InternalDate)`, or `own.movedAt(key)` exists with `!a.H.InternalDate.After(at)`. If it is a return and `own.explains(a)` → `returnExplained` (no event). Otherwise `returnTrained` with `trainEvent{Sender: a.H.From, Folder: inbox, MessageKey: a.Key}`, except an own/empty From, which is `returnExplained` (no event, still never classified).

### Task 5: wire training into `Process`

**Files:** Modify `internal/engine/process.go`, `internal/engine/train.go`, `internal/engine/undo.go`, `internal/engine/process_test.go` (or new `internal/engine/train_process_test.go`), `cmd/quietbox/once.go`.

**Interfaces:**
- Consumes Tasks 1, 2, 4.
- Produces: `ProcessReport.Trained []TrainOutcome` with `type TrainOutcome struct{ Sender, From, To, Source, Status string }` (`Status`: `TrainDone` | `TrainWould`; `From` = the folder the route had, `""` if none). `once`/`run` print `trained <sender>: <from> -> <to>` (`would train ...` in dry runs) and a `trained N sender(s)` summary line.
- Ordering in `Process`: `processSent`, then `processTyped`, then `processInbox`.

Behaviour to build:
- `processTyped(ctx, cfg, b, st, o, k, rep)`: for each configured folder except INBOX and Sent that exists on the server: `ensureCursor` (a folder with no cursor gets one at current UIDNEXT in a real run, with warning `training from moves starts now for <folder>; earlier moves are not learned`; skipped in a dry run), `checkCursor` (UIDVALIDITY change → existing warning, no training), `FetchFrom`, build `arrival`s, `ownMoves` from `st.Audit`. Every arrival upserts `messages`; unexplained ones with `fileEvent` ok become events. Cursor advances like INBOX (`max(NextUID, maxUID+1, status.UIDNext)`), in the **same** `st.Update` as the events. Folders are processed in config order.
- `applyTraining(ctx, st, k *classify.Knowledge, events []trainEvent, source string, o ProcessOptions) ([]TrainOutcome, error)`: events in order, later wins per sender; an event that equals the current *trained* route (`k.Senders[s].Folder == e.Folder && .Trained && !.Mixed`) is a no-op; otherwise update `k.Senders[sender] = SenderRoute{Folder, Trained: true, Reason: "moved from <old> to <new>"}` in memory (also in dry runs) and, in a real run, `UpsertTrainedSender` + `AddTraining`. Conflicting events for one sender in a pass add the warning `moves for <sender> disagreed in one pass; the last one won`.
- `processInbox`: before the classify loop, run `inboxArrival` on every fetched message (using `st.Messages` and `ownMoves`). `returnTrained` events go through `applyTraining`; `returnExplained`/`returnTrained` messages are removed from `messages` and **never classified or moved**, regardless of `\Seen`/`\Flagged`; they count in `rep.Skipped`. All other messages proceed as in M3 with the updated `k`.
- `fileMessage`: after a `done` move, `PutMessage(key, destination, h.InternalDate)`. `undoOne`: after a restore, `ForgetMessage(r.MessageKey)`.
