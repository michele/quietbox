quietbox

Getting started

From install to a quieter inbox. quietbox moves no mail until step 7, so you can stop at any point before that and your inbox is untouched.

1. Before you start

You need a mailbox on Fastmail, Gmail, or another IMAP server that supports MOVE and UIDPLUS. Microsoft 365 and Outlook.com are not supported, because they only allow IMAP through OAuth2.

You also need an app password: a separate password your provider creates for one application, so quietbox never sees your real one.

  • Fastmail: Settings, Privacy & Security, Integrations, New app password, access "Mail (IMAP)".
  • Gmail: myaccount.google.com/apppasswords. It needs 2-Step Verification, and Google Workspace admins can switch app passwords off.

quietbox is new and has not been thoroughly tested. It never deletes mail and undo reverses its moves, but keep a backup of anything you cannot afford to lose, and use the dry runs below.

2. Install

curl -fsSL https://quietbox.sh/install.sh | sh
quietbox --version

This puts quietbox in ~/.local/bin, so make sure that is on your PATH. For other ways to install (archives, go install, a container), see the install section.

3. Write a config

quietbox reads one TOML file, by default ~/.config/quietbox/config.toml. Start from the example for your provider, in examples/ on GitHub (Fastmail, Gmail, or generic IMAP). A minimal one looks like this:

[imap]
host = "imap.fastmail.com"       # Gmail: imap.gmail.com
username = "you@example.com"

[[folder]]
name = "INBOX"
type = "important"

[[folder]]
name = "+QuietLater"
type = "later"

[[folder]]
name = "+QuietNews"
type = "newsletter"

[[folder]]
name = "+QuietBulk"
type = "bulk"

[[folder]]
name = "+QuietBlackHole"
type = "blackhole"

The folder names are yours to choose. The + in front just makes them sort together. If you already have folders you file mail into, name them here with the type that fits, and quietbox learns from them in step 5.

The password never goes in the file. For now, put it in the environment:

export QUIETBOX_IMAP_PASSWORD='your-app-password'

For anything that runs unattended, use a password_file or password_command instead (see step 8).

Coming from SaneBox? Keep its folder names (SaneLater, SaneNews and so on) instead, so quietbox can learn from what SaneBox already filed. The migration guide walks through it.

4. Check the connection

quietbox check

check connects, prints what the server supports, and shows which of your folders exist. It needs MOVE and UIDPLUS, and quietbox refuses to run without them. It changes nothing.

5. Learn from your mailbox

# read-only: shows what it would learn
quietbox init --dry-run

# creates missing folders (it asks first) and learns
quietbox init

init reads message headers only, never bodies, and marks nothing as read. It looks at your folders, your Sent mail, and the last six months of INBOX, and works out which sender belongs where. It writes a CSV report next to its database, one row per sender with the route it chose and why. Open it before going on.

If nothing has ever sorted this mailbox, everything is sitting in INBOX and there is nothing to learn from. Use quietbox init --fresh --backlog 30d instead, and read Starting on a never-managed account first.

6. See what it would do

# what would happen to your inbox right now, and why
quietbox scan

# how well it would have done on mail you already sorted
quietbox eval

# what it would file on the next pass
quietbox once --dry-run

All three only read. Look for mail in the list that should have stayed in your inbox. In eval, the number to watch is hidden important: inbox mail quietbox would have filed away. If something looks wrong, quietbox explain says why a given message was filed where it was, and quietbox senders set sender@example.com INBOX pins a sender to your inbox.

7. File mail for real

quietbox once

This files the mail that has arrived since init. Your existing inbox is never swept. Mail you have already read or flagged stays where it is, and so does anything it cannot place. Every move is written to the audit log before it happens.

8. Keep it running

You have two choices. Run quietbox once from cron every few minutes, or run quietbox run as a daemon that waits on your inbox and files mail as it arrives.

Either way, an unattended process should not read the password from your shell. Put it in a file only you can read (chmod 600), or fetch it from a keychain or password manager:

[imap]
host = "imap.fastmail.com"
username = "you@example.com"
password_file = "~/.config/quietbox/fastmail.pw"
# or: password_command = "security find-generic-password -s quietbox -w"

[[folder]]
name = "INBOX"
type = "important"

[[folder]]
name = "+QuietLater"
type = "later"

To start the daemon at boot, use the systemd units or the container image. Restart run after you edit the config.

For a second mailbox, save its config as ~/.config/quietbox/NAME.toml and add --account NAME to each command. Each account gets its own process and database.

9. Teach it by moving mail

From any mail app, move a message into one of your quietbox folders and that sender's mail goes there from now on. Move a message back to INBOX and that sender stays in your inbox. One move is enough, your latest move wins, and it beats anything quietbox learned or detected. Training changes quietbox's own database, never your mailbox.

To block a sender, move one of their messages into the blackhole folder. Nothing is deleted at that point. After 30 days, quietbox moves the mail to Trash.

10. See what it is doing

quietbox stats
quietbox stats --since 7d

After a few days, stats shows how many messages quietbox filed, an estimate of the time that saved you, where the mail went, and how often you had to correct it. It reads only quietbox's own database, so it is safe to run at any time, even while quietbox is running.

  • Time saved is an estimate: messages filed times a number of seconds per message (5 by default). Set seconds_per_message in a [stats] section of your config to what handling a message by hand really costs you.
  • Corrected by you counts messages quietbox filed that you then moved yourself, back to your inbox or into another folder. The error rate is that count divided by the messages filed.
  • The error rate is a floor. It only counts mistakes you noticed and fixed, not mail that was filed away wrongly and that you never missed. Use quietbox eval to check for that before you trust it.

11. Change your mind

quietbox undo --since 1h

undo moves back what quietbox filed in that time. It leaves alone anything you moved yourself since, and it will not file those messages again.

When something is off

  • Login fails: use the app password, not your account password. On Gmail, check that IMAP is switched on.
  • check says MOVE or UIDPLUS is missing: your server cannot be used safely, and quietbox will not try.
  • "another quietbox is still running": only one quietbox acts on a mailbox at a time. Wait for the other one, or see Locks.
  • A message was filed wrongly: move it back, or run quietbox explain on it.
  • Mail it should have filed is still in your inbox: expected now and then. quietbox leaves mail alone when it is unsure. Move it to the right folder once and the sender is learned.
